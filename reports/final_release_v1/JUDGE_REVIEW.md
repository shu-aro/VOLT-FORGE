# Final judge view

Recommendation: review the alternative PDF first. It makes the problem → design → challenge → evidence argument easier to scan while retaining a large actual prototype and the traced comparison table. The blue version preserves the previously approved visual system and makes the seven rubric categories explicit.

The strongest evidence is a working, repeatable software prototype: a complete browser flow, 4,006 reproduced cases, an explicit sizing gate, saved-context comparisons, exact samples, reviewed AI edits and export/replay. Scope and operating assumptions are visible. The appendix reconstructs the argument rather than listing repository contents.

The remaining weaknesses are evidential, not cosmetic: predictive voltage/temperature accuracy is unestablished; board behaviour and fault isolation have not been measured; the selected two-cell design has no spare; prices/adoption are untested and the old full-suite build estimate has substantial role/effort assumptions. None should be disguised by a KPI, synthetic numerical reference or selected measurement slice.

95/100 remains a target, not a defensible promise. My subjective pre-submission forecast is around 85–91 depending on how judges weight a software prototype with transparent model limitations. This is not an independent awarded score. No deduction is assumed simply because the team did not conduct physical hardware work or user trials; the important issue is whether the claims exceed the evidence. New physical work is not being imposed as a Round 1 condition.
